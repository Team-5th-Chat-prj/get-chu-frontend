# E2E 트러블슈팅 슬라이드 초안

## 슬라이드 제목

**로컬 환경 차이로 인한 통합 실행 문제와 E2E 테스트 도입**

---

## PPT 본문용 요약 버전

### 문제 상황
- 프론트엔드와 백엔드를 연결한 뒤, 제 로컬 환경에서는 정상 동작했지만 다른 팀원의 로컬 환경에서는 동일한 흐름이 재현되지 않았습니다.
- 백엔드는 `docker-compose.yml`의 `restart: unless-stopped` 설정 때문에 오류 발생 시 무한 재시도 상태에 빠져 원인 파악이 어려웠습니다.
- 팀원 환경에서는 더미 데이터 주입이 제대로 되지 않아 로그인, 시드 데이터 기반 화면, 테스트 계정 흐름이 정상적으로 동작하지 않는 문제가 있었습니다.

### 원인
- 개인별 로컬 실행 환경 차이
- Docker 재시작 정책으로 인한 오류 은닉
- 더미 데이터/초기 상태가 환경마다 다르게 유지됨

### 해결 방법
- Playwright 기반 E2E 테스트를 도입해 회원가입, 로그인, 동네 인증, 찜, 채팅, 예약, 거래, 리뷰 등의 핵심 사용자 흐름을 자동화했습니다.
- 특정 개인의 PC가 아니라 **다른 팀원의 로컬 환경에서도 동일한 시나리오가 실행되는지** 확인할 수 있도록 테스트 기준을 통일했습니다.
- 발표용 demo 시나리오와 일반 검증용 E2E를 분리해, 품질 검증과 시연 자동화를 동시에 활용했습니다.

### 결과
- “내 환경에서는 된다”가 아니라 “팀원 환경에서도 같은 흐름이 재현된다”는 기준으로 문제를 검증할 수 있게 되었습니다.
- 더미 데이터, 백엔드 초기화, 프론트-백엔드 연결 상태에서 발생하는 환경 차이 문제를 더 빠르게 발견하고 공유할 수 있었습니다.
- E2E 테스트는 단순 기능 테스트를 넘어 **팀 공통 실행 환경 검증 도구** 역할을 하게 되었습니다.

---

## 발표용 압축 버전

### 문제
- 제 로컬에서는 정상 동작했지만 팀원 환경에서는 백엔드 무한 재시도와 더미 데이터 누락으로 핵심 기능이 동일하게 재현되지 않았습니다.

### 해결
- Playwright E2E 테스트로 회원가입부터 리뷰까지 핵심 사용자 흐름을 자동화하고, 팀원 로컬 환경에서도 동일하게 실행되는지 검증했습니다.

### 결과
- 환경 차이에서 발생하는 문제를 빠르게 발견·공유할 수 있었고, 기능 검증 기준을 팀 전체에 공통화할 수 있었습니다.

---

## 슬라이드 한 장용 3줄 버전

- **문제**: 로컬마다 Docker 재시작 정책과 더미 데이터 상태가 달라 프론트-백엔드 통합 흐름이 동일하게 재현되지 않았습니다.
- **해결**: Playwright E2E 테스트로 핵심 사용자 흐름을 자동화하고, 다른 팀원 환경에서도 실행 가능한지 검증했습니다.
- **결과**: 환경 차이 문제를 조기에 발견하고, 팀 공통의 실행/검증 기준을 마련했습니다.

---

## 발표 멘트 예시

“통합 과정에서 가장 큰 문제는 제 환경에서는 되는데 다른 팀원 환경에서는 같은 흐름이 재현되지 않는다는 점이었습니다.  
특히 Docker 재시작 정책 때문에 백엔드 오류가 무한 재시도로 가려졌고, 더미 데이터 주입 상태도 환경마다 달라 로그인이나 시드 데이터 기반 화면이 정상 동작하지 않는 경우가 있었습니다.  
이 문제를 해결하기 위해 Playwright 기반 E2E 테스트를 도입해, 핵심 사용자 흐름을 자동화하고 팀원 로컬 환경에서도 동일하게 실행되는지 검증했습니다.”
